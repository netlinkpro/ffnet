# Slice 1.5 — Error fidelity across the asm/C boundary

Status: approved 2026-05-23

## Context

Slice 1 is complete and verified end-to-end on Linux. All asm-side routines that
make syscalls already return `-errno` on failure, but the C wrappers collapse
every failure to `FFE_IO`:

```c
/* src/libffnet/tcp.c */
static int map_io(int rc) { return rc < 0 ? FFE_IO : rc; }
```

This is the most common failure mode for two flavors of future debugging:

1. **Slice 1.7 (multi-client / event loop)** needs to distinguish `EAGAIN` from
   a real I/O failure — without that, an event-loop `read` returning "not ready"
   is indistinguishable from a broken socket.
2. **Current diagnostics**: `FFE_IO` tells the operator nothing. `Address
   already in use` and `Connection reset` both print as the same useless string.

## Goals

- Translate `-errno` from asm-side returns into a small set of meaningful
  `FFE_*` codes; collapse the long tail to `FFE_IO`.
- Preserve `errno` across the asm/C boundary so callers can `strerror(errno)`
  themselves when they want the human message.
- Update CLI log call sites to include both the FFE_* name and the
  human-readable description.
- Add tests that exercise at least two of the new codes against real syscall
  failures (not mocks).

## Non-goals

- Defining an `FFE_*` code for every `errno` value. The point is a useful
  subset, not a 1:1 mapping.
- Changing anything about non-blocking I/O semantics. `FFE_AGAIN` is added now
  as a placeholder for slice 1.7; no current code path will return it.
- Thread-safe error reporting. Slice 1 is single-threaded; `errno` is already
  thread-local on glibc.
- Replacing the existing `Protocol` ABI or any other interface shape.

## API additions

### New error codes (`include/ffnet/ffutil.h`)

Appended after the existing FFE_INVAL:

```c
#define FFE_AGAIN    -7   /* EAGAIN / EWOULDBLOCK — try again              */
#define FFE_REFUSED  -8   /* ECONNREFUSED                                  */
#define FFE_RESET    -9   /* ECONNRESET — peer reset the connection        */
#define FFE_PIPE    -10   /* EPIPE — broken pipe on write                  */
#define FFE_TIMEOUT -11   /* ETIMEDOUT                                     */
#define FFE_PERM    -12   /* EACCES / EPERM                                */
#define FFE_INTR    -13   /* EINTR — signal interrupted the syscall        */
```

Numeric assignments are ABI; do not renumber existing codes.

### Translation helper

```c
/* Translate a negative errno (-EAGAIN, -ECONNREFUSED, etc.) into a
 * matching FFE_* code. Returns FFE_IO for unrecognized values.
 * Always sets `errno = -negative_errno` as a side effect so callers can
 * follow up with strerror(errno) for a human description. */
int ffutil_map_errno(int negative_errno);
```

Defined in `src/libffutil/log.c` (same translation unit as `ffutil_strerror`).

### `ffutil_strerror` extension

Add cases for the seven new codes. Implementation stays a simple switch over
the negative integer.

### `ffutil_strerror_v` — verbose formatter for log lines

```c
/* Format an FFE_* code for a log line. For I/O-class codes (FFE_IO,
 * FFE_AGAIN, FFE_REFUSED, FFE_RESET, FFE_PIPE, FFE_TIMEOUT, FFE_PERM,
 * FFE_INTR), appends " (<strerror>)" using the current errno. For
 * non-IO codes (FFE_OK, FFE_PROTOCOL, FFE_BADKEY, FFE_NOMEM, FFE_CLOSED,
 * FFE_INVAL), returns just the FFE_* name to avoid printing stale errno
 * noise.
 *
 * Returns a pointer to a static buffer; not thread-safe. Slice 1 is
 * single-threaded; revisit when 1.7 introduces threading. */
const char *ffutil_strerror_v(int rc);
```

This is the function CLI log sites use, not the bare `ffutil_strerror` +
`strerror(errno)` pair. It is the load-bearing reason the design splits the
new error codes into an "I/O class" range (7..13) versus the original
"non-I/O class" range (1..6) — the helper uses the numeric range to
decide whether errno is meaningful.

## Tests added

In `tests/test_tcp.c`, after the existing "child clean exit" case:

1. **`connect-refused`**: open an ephemeral listener, query its port, close it,
   then attempt a client `connect()` to `127.0.0.1:<port>`. Expect `FFE_REFUSED`
   from the wrapper (or document if we add `ffnet_tcp_connect()` — see "Open
   questions"). Actually for this slice we can just verify the libc connect
   path: assert that *if* a client connect fails with ECONNREFUSED, the
   translation in tcp.c (when we eventually have ffnet_tcp_connect) maps it.
   For now: small standalone test that calls `ffutil_map_errno(-ECONNREFUSED)`
   and asserts the result is `FFE_REFUSED` with `errno == ECONNREFUSED`.

2. **`write-to-closed`**: open a `socketpair(AF_UNIX, SOCK_STREAM, 0, fds)`,
   close one end, write a byte to the other. libc returns `-1` with
   `errno == EPIPE`. Test code calls `ffutil_map_errno(-errno)` directly on
   the result and asserts `FFE_PIPE` plus `errno == EPIPE` round-trip.
   `SIGPIPE` is ignored at the start of `main()` of the test binary so the
   write returns instead of killing the process.

These tests don't require a new `ffnet_tcp_connect()` API. They exercise the
translation table directly plus one real syscall (EPIPE), which is the
load-bearing behavior.

After implementation:

```
make clean && make           # builds ffnet binary with new codes
make test                    # all unit tests including the two new cases
make itest                   # ws-echo integration test still green
```

Manual smoke:

```
# 1. Confirm log line includes strerror description
./build/ffnet ws-echo --listen 0.0.0.0:80    # likely EACCES on non-root
# expected log line: bind_listen 0.0.0.0:80: FFE_PERM (Permission denied)

# 2. Confirm address-in-use surfaces clearly
./build/ffnet ws-echo --listen 127.0.0.1:9000 &   # session 1
./build/ffnet ws-echo --listen 127.0.0.1:9000     # session 2
# expected: bind_listen 127.0.0.1:9000: FFE_IO (Address already in use)
# (EADDRINUSE doesn't get a dedicated FFE_* — it falls into FFE_IO,
#  but strerror still names it correctly.)
```

## Risks and open questions

1. **SIGPIPE behavior**. Ignoring it globally in `cli/ffnet.c::main` is the
   common pattern for network servers and matches Python, nginx, etc. Worth
   noting: this changes behavior for the `ffnet` binary, not for the
   libraries. Library users who link `libffproto.a` into their own binary
   need to handle SIGPIPE themselves. This is consistent with how nginx,
   libcurl, and others document it.

2. **`ffnet_tcp_connect()`**. We don't have a connect primitive yet (slice 1
   is server-only). The Slice 1.5 design intentionally doesn't add one —
   `connect-refused` testing is done by mapping `-ECONNREFUSED` directly,
   which is sufficient to validate the translation. A `ffnet_tcp_connect()`
   surface lands when slice 2 (HTTP) adds the first client. Flagging so we
   don't accumulate the debt silently.

3. **Numeric ABI stability**. The seven new codes use sequential negative
   values 7–13. Any future code is appended; never renumbered. Documented in
   `ffutil.h` comment.

4. **`errno` is global, and stale-`errno` poisoning is a real failure mode**.
   Setting `errno` as a side effect of returning an FFE_* code is a libc
   idiom, but it means that if a *non-IO* code (e.g. `FFE_BADKEY` from
   handshake parsing) is followed by a naive `strerror(errno)`, the operator
   sees the description of whatever syscall ran last (often misleading or
   just "Success"). The `ffutil_strerror_v` helper exists specifically to
   handle this: it only appends `strerror(errno)` when `rc` is in the
   I/O-class range. CLI log sites use `ffutil_strerror_v`, not the bare
   `ffutil_strerror` + `strerror(errno)` pair.

## Out of scope (deferred to later slices)

- `FFE_AGAIN`-aware code paths (slice 1.7, multi-client).
- `ffnet_tcp_connect()` API (slice 2, when HTTP needs a client).
- Per-connection error context beyond `errno` (no need yet).
- Removing the `errno` side-effect coupling by introducing a context struct
  (deferred until threading is on the table — slice 1.7+).
