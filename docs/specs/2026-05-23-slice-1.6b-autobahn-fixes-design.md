# Slice 1.6b — Autobahn fixes

Status: approved 2026-05-23

## Context

Slice 1.6a (`849bcf0`) integrated Autobahn|TestSuite and captured a baseline
of **181 / 301 strict pass (60.1%)** for `ws-echo` at commit `42bc225`.
Failures cluster cleanly:

- §6 UTF-8 handling: **77 cases** — we don't validate.
- §9 limits / large messages: **16 cases** — mix of fragmentation-related
  and genuine large-payload timeouts.
- §5 fragmentation: **9 cases** — we reject all `FIN=0` data frames.
- §3 reserved bits: **6 cases** — we don't check `RSV1|RSV2|RSV3`.
- §2 oversize ping (2.5), §10.1.1 (auto-fragmented echo): 2 scattered cases.

Full breakdown in [docs/autobahn-baseline-2026-05-23.md](../autobahn-baseline-2026-05-23.md).

The §6 + §5 + §3 + scattered cases (~95 of 110 failures) are tractable in
the current single-threaded blocking model. The hard subset of §9 (large
messages whose echo round-trip exceeds Autobahn's timeout window) genuinely
needs the slice 1.7 event loop and is explicitly deferred.

## Goals

- Reach **≥ 95% strict pass** on Autobahn (~285 / 301).
- Make `ws-echo` correctly handle: fragmentation, UTF-8 validation, reserved
  bits, control-frame constraints, and clean Close on protocol errors.
- Preserve existing behavior: `make test` and `make itest` continue to pass
  with no regressions to the basic handshake or text/binary echo.

## Non-goals

- The §9 cases that require non-blocking I/O. Documented as 1.7 dependencies
  in the post-run report.
- Permessage-deflate (§12, §13). Never in scope for the 1.x slice family.
- Optimizing the UTF-8 validator with SIMD or asm. Plain C DFA is fine
  for slice 1.6b; perf is slice 1.8.
- Changing the `Protocol` ABI further. Same shape as after slice 1.5.

## Implementation order

Implementation proceeds in this order so each addition is verifiable in
isolation. Bundle into commits at logical seams (spec, plan, implementation,
results) per the project's cadence.

1. **Reserved-bit check** (covers §3, 6 cases). In `read_one_frame`, after
   loading `hdr[0]`: if `(hdr[0] & 0x70) != 0`, error → Close(1002).
2. **Control-frame validation** (covers 2.5 + a few scattered). For
   opcodes ≥ 0x8 (control): payload length must be ≤125 and FIN must be 1.
   Reject otherwise → Close(1002).
3. **Reserved-opcode polish** (covers §4: 4 NON-STRICT → OK). For opcodes
   0x3–0x7 and 0xB–0xF, send Close(1002) before returning FFE_PROTOCOL.
   Currently we just return without a Close, which Autobahn flags as
   non-strict.
4. **Fragmentation** (covers §5: 9 cases + 10.1.1 + a meaningful chunk of
   §9). New `WsConn.fragment_opcode` tracks an in-progress message. State
   machine:
   - Receive TEXT/BINARY with FIN=1, no fragment in progress → return.
   - Receive TEXT/BINARY with FIN=0, no fragment in progress → start
     fragment, save opcode, accumulate payload, continue.
   - Receive TEXT/BINARY when fragment in progress → protocol error
     (Close 1002).
   - Receive CONT with no fragment in progress → protocol error
     (Close 1002).
   - Receive CONT with fragment in progress → accumulate; if FIN=1,
     complete (clear state, return) else continue.
   - Control frames may interleave freely; they don't touch fragment
     state.
   Payload accumulates in the caller's FrameBuf passed to `read_frame`
   (same buffer reused across fragments; cleared only on full message).
5. **Streaming UTF-8 validator** (covers §6: 77 cases). New
   `src/libffproto/ws/utf8.{c,h}` implements Bjoern Hoehrmann's DFA
   (public domain, ~25 lines + 364-byte transition table). Interface:
   ```c
   #define FF_UTF8_ACCEPT 0
   #define FF_UTF8_REJECT 12
   /* Feed bytes into the validator; returns the new state.
    * Caller starts a new message with `state = FF_UTF8_ACCEPT`.
    * End-of-message is valid iff state == FF_UTF8_ACCEPT after the last byte. */
   uint32_t ff_utf8_decode(uint32_t state, uint8_t byte);
   ```
   In `ws_read_frame`, when payload bytes arrive for a TEXT fragment
   (whether initial or continuation), feed them through the validator.
   On REJECT → Close(1007) and return FFE_PROTOCOL. On FIN with state
   != ACCEPT → same (incomplete codepoint at end of message). Reset
   state to ACCEPT at the start of each new TEXT message.
6. **Clean Close on protocol errors** (bumps many UNCLEAN → CLEAN). Helper:
   ```c
   /* Send a Close frame with the given status. Best-effort; on write
    * failure just return rc — the caller is going to close the fd anyway. */
   static int ws_close_with(int fd, uint16_t code);
   ```
   Used at every `return FFE_PROTOCOL` and at the UTF-8 reject sites in
   `ws_read_frame`. Status codes:
   - 1002 protocol error (reserved bits/opcodes, fragmentation rule
     violations, control-frame violations)
   - 1007 invalid frame payload data (UTF-8 validation failure)
   - 1009 message too big (reserved; not enforced this slice, but the
     helper takes any code)

## `WsConn` evolution

```c
typedef struct WsConn {
    uint8_t  last_opcode;       /* slice 1: echo opcode matching             */
    uint8_t  fragment_opcode;   /* 0 / FFWS_OP_TEXT / FFWS_OP_BINARY         */
    uint32_t utf8_state;        /* DFA state; reset at start of each text msg */
} WsConn;
```

Total size: 8 bytes (with alignment). Still trivially small.

## Risks and open questions

1. **Close-handshake timing**. RFC 6455 says after sending a Close, the
   server SHOULD wait for the peer's Close ack before TCP-closing. Slice
   1.6b will send Close and close immediately (no waiting). Autobahn
   doesn't strictly require the wait, and adding it requires either a
   select/poll loop or a brief blocking read — both flirt with slice
   1.7's scope. Accepted limitation; reassess if specific Autobahn cases
   fail because of it.

2. **Fragment payload bound**. We accumulate fragments into the caller's
   FrameBuf, which grows via `realloc`. A hostile peer could send a 4 GB
   fragmented message and exhaust RAM. Slice 1.6b adds no max-size
   enforcement; treat as accepted risk for an unauthenticated server.
   Slice 1.7 / 1.8 should add `WS_MAX_MESSAGE` and Close(1009) on
   overflow.

3. **UTF-8 validator licensing**. Hoehrmann's DFA is public-domain
   (declared by the author at https://bjoern.hoehrmann.de/utf-8/decoder/dfa/).
   No relicensing issue with our LGPL-2.1-or-later codebase; include an
   attribution comment in `utf8.c` and the file gets the standard SPDX
   header alongside.

4. **NON-STRICT vs OK delta**. The post-run doc should compare strict
   (OK only) and lenient (OK + NON-STRICT) pass rates so we can see
   which fixes upgrade NON-STRICT to OK.
