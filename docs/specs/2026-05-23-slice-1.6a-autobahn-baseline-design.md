# Slice 1.6a — Autobahn baseline

Status: approved 2026-05-23

## Context

Slice 1.5 (error fidelity) is complete and verified. The broader "harden slice
1" effort was decomposed into 1.5 (errors) → 1.6 (Autobahn pass) → 1.7 (event
loop) → 1.8 (perf). This is the first half of 1.6.

`ws-echo` currently passes our hand-written integration test
(`tests/test_ws_echo.py` covers handshake, text echo, binary echo) but that
suite is intentionally minimal. RFC 6455 has dozens of edge cases — UTF-8
validation, fragmentation, reserved bits/opcodes, oversized frames, control-
frame constraints, close-code semantics — and the Autobahn|TestSuite is the
canonical compliance fuzzer that exercises all of them (~250 cases excluding
the permessage-deflate extension).

The decision in 1.6's outer brainstorm was **baseline first, then decide**.
This spec covers only the baseline — Phase A. Phase B (fix the failures)
will be brainstormed and specced separately once we have real failure data.

## Goals

- Make Autobahn|TestSuite runnable against `ws-echo` with one command on the
  shaiman dev box (`make autobahn`).
- Produce a reproducible per-section pass / fail / non-strict report.
- Commit a baseline snapshot (markdown summary, not raw HTML) so Phase B has
  concrete target case IDs to fix.

## Non-goals

- Fixing any failure surfaced by the baseline run. That's Phase B.
- Running Autobahn in CI / as part of `make test`. It's heavy (Docker, ~5 min)
  and needs an external image; gated behind its own `make autobahn` target.
- Implementing `permessage-deflate` (Autobahn sections 12.x and 13.x). The
  extension is out of scope for the entire 1.x slice family; cases are
  excluded from the run, not run-and-failed.

## Components

### `tests/autobahn/fuzzingclient.json`

Autobahn's fuzzingclient config:

```json
{
    "outdir": "./reports/servers",
    "servers": [
        {
            "agent": "ffnet-ws-echo",
            "url":   "ws://host.docker.internal:9001"
        }
    ],
    "cases":        ["*"],
    "exclude-cases": ["12.*", "13.*"],
    "exclude-agent-cases": {}
}
```

`host.docker.internal` resolves to the host from inside the container on
Docker Desktop and (with `--add-host=host.docker.internal:host-gateway`) on
plain Linux Docker. The wrapper script passes that flag.

### `tests/autobahn/run.sh`

Shell wrapper. Responsibilities:

1. `make` if needed; ensure `build/ffnet` exists.
2. Launch `./build/ffnet ws-echo --listen 0.0.0.0:9001` in the background;
   wait for the "listening on" line on stdout; capture its PID.
3. `docker run --rm --network host -v $PWD/tests/autobahn:/config -v
   $PWD/tests/autobahn/reports:/reports crossbario/autobahn-testsuite:latest
   wstest -m fuzzingclient -s /config/fuzzingclient.json`
4. Kill the ws-echo server.
5. Parse `tests/autobahn/reports/servers/index.json` — count cases in each
   bucket (`OK`, `NON-STRICT`, `FAILED`, `INFORMATIONAL`).
6. Print a one-line summary plus a section-level breakdown to stdout.
7. Exit 0 unconditionally on script success — Autobahn failures are the
   point of the diagnostic run, not script errors. Exit nonzero only if
   the script itself can't run (Docker missing, server didn't start, JSON
   not produced).

The script does not auto-fail the build on Autobahn results; CI gating is
intentionally deferred.

### `Makefile`

Add a phony target:

```make
.PHONY: autobahn
autobahn: $(BUILD)/ffnet
	tests/autobahn/run.sh
```

Not added to `all` or `test` — explicit invocation only.

### `.gitignore`

Add `tests/autobahn/reports/`. The raw HTML/JSON reports are megabytes,
reproducible, and noisy. Only the committed markdown summary tracks state.

### `docs/autobahn-baseline-2026-05-23.md`

Committed snapshot. Contents:

- ffnet commit SHA (the HEAD this baseline was measured against).
- Autobahn|TestSuite image tag (`crossbario/autobahn-testsuite:<digest>`).
- Date and machine.
- Per-section table: section name, total cases, passed, non-strict, failed.
- Bulleted list of FAIL case IDs (e.g. `5.1, 5.2, 6.4.1, 7.3.1, ...`) so
  Phase B can grep them.
- Reproduction commands (literally `make autobahn`).
- Three to five sentences interpreting the result — which categories
  dominate the failures, rough estimate of effort to land Phase B.

This is the Phase A deliverable.

## Risks and open questions

1. **`host.docker.internal` on Ubuntu 24.04.** Docker Desktop adds this name
   automatically; the daemon on shaiman is the open-source `docker.io`
   package. The wrapper script passes `--add-host=host.docker.internal:host-gateway`
   which works on Docker 20.10+ (shaiman has 24.x; safe).
2. **Image pull bandwidth.** The Autobahn image is ~400 MB. First run on
   shaiman will be slow; subsequent runs use the cached image.
3. **Pinning the image tag.** We don't pin a specific image digest in the
   first version (use `:latest`). The baseline snapshot records the
   resolved digest from the actual run, so the snapshot itself is
   reproducible. If Autobahn updates change results dramatically, Phase B
   may want to pin.
4. **Port collision.** Port 9001 hardcoded. If shaiman already uses it for
   something, the script bails clearly. Trivial to change if needed.
5. **No CI integration.** Intentional. CI would need a Docker-capable
   runner; gating on Autobahn results before fixes is premature.

## Out of scope (deferred to Phase B and beyond)

- Any production-code change to fix what Autobahn flags.
- Validation that ws-echo passes Autobahn — explicitly *not* the success
  criterion. Phase A succeeds when the baseline is captured.
- Permessage-deflate (sections 12.x, 13.x) support, ever in the 1.x family.
- A CI workflow for Autobahn.

## Estimate

~30 min of setup (script, config, Makefile target). One ~5-10 min Autobahn
run on shaiman. ~10 min to write the baseline doc. Total: under an hour.
