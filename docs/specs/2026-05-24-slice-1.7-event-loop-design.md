# Slice 1.7 — Non-blocking event loop + multi-worker server

Status: approved 2026-05-24

## Context

Slices 1.5 and 1.6 hardened the single-connection blocking model: errors are
specific, `ws-echo` is RFC 6455-compliant (96.3% Autobahn strict pass, zero
FAILED). The model's remaining limit is structural — one client at a time
per process. A second client connecting while the first is mid-message just
sits in the accept backlog.

Slice 1.7 makes `ffnet` a concurrent server. The model:

- Single-thread epoll-based event loop (reactor pattern, nginx/redis style).
- N worker threads, each running its own loop bound to the same listen port
  via `SO_REUSEPORT` (kernel distributes incoming SYNs across workers).
- Protocol modules evolve from blocking call-style ABI v2 to event-driven
  ABI v3.

The 1.6b post-run discovered the event loop is **not needed for RFC
compliance** (blocking + `realloc` handles 16 MB messages fine when only one
client is active). 1.7 is therefore about **concurrency**, not correctness.
Success criterion is "N clients served at once without head-of-line
blocking," not "more Autobahn cases pass."

## Goals

- `ffnet ws-echo --listen 127.0.0.1:PORT --workers N` serves M ≥ 2 clients
  concurrently with no head-of-line blocking.
- Autobahn pass rate stays at ≥ 96.3% (same as 1.6b — no regression).
- A new `ffnet tcp-echo` subcommand demonstrates the bare event loop
  without protocol-module complexity, useful for benchmarking and as a
  reference for future protocol authors.
- `Protocol` ABI evolves to v3 (event-driven). The WS module is the only
  current consumer; rewrite it to fit.

## Non-goals

- io_uring or any backend other than epoll. Linux/x86_64-only is the
  established slice 1 scope.
- Asm-level work on the event loop. Pure C is fine; perf is slice 1.8.
- Edge-triggered epoll (`EPOLLET`). Level-triggered is the simpler
  starting point.
- Inter-worker IPC or shared state. Each worker owns its connections;
  there is no cross-worker coordination beyond the kernel's SO_REUSEPORT
  load balancing.
- TLS, HTTP/1.1, or any second protocol — those are slice 2+.
- A graceful shutdown path beyond SIGINT → close listen sockets, drain
  connections, exit. (Connection draining is best-effort.)
- Backwards compatibility with Protocol ABI v2. v2 has one consumer (WS),
  which we migrate in this slice; v2 is deleted.

## Architecture

```
        ┌──────────────────────────────────────────────────┐
        │  cli/cmd_ws_echo.c        cli/cmd_tcp_echo.c     │
        │  (~20 lines each: parse args, call server_run)   │
        └──────────────────────────────────────────────────┘
                        │            │
                        ▼            ▼
        ┌──────────────────────────────────────────────────┐
        │  ffnet_server_run(proto, host, port, workers)    │
        │  src/libffnet/server.c                           │
        │  • Spawns N pthreads                             │
        │  • Each: create listen fd, SO_REUSEPORT, bind,   │
        │    new evloop, register accept callback, run     │
        └──────────────────────────────────────────────────┘
                        │            │
                        ▼            ▼
        ┌──────────────────┐  ┌────────────────────────────┐
        │  FfEvLoop        │  │  const Protocol *proto     │
        │  src/libffnet/   │  │  • open(fd, &ctx)          │
        │    eventloop.c   │  │  • on_event(fd, ctx, evts) │
        │  • epoll_wait    │  │  • close(fd, ctx)          │
        │  • add/mod/del   │  │                            │
        │  • run/stop      │  │  WS module = state machine │
        └──────────────────┘  └────────────────────────────┘
```

Each worker is a complete server: own listen fd, own loop, own connection
table. There is no shared mutable state between workers. `WsConn` lives in
exactly one worker's address space.

## Components

### Low-level event loop — `src/libffnet/eventloop.c`

epoll-based wrapper. Single thread per `FfEvLoop`. Level-triggered (no
`EPOLLET`).

Public API in `include/ffnet/ffnet.h`:

```c
typedef struct FfEvLoop FfEvLoop;

#define FF_EV_READ  (1u << 0)
#define FF_EV_WRITE (1u << 1)

typedef void (*FfEvCallback)(FfEvLoop *loop, int fd, uint32_t events, void *ctx);

FfEvLoop *ffnet_evloop_new(void);
void      ffnet_evloop_free(FfEvLoop *loop);

int  ffnet_evloop_add(FfEvLoop *loop, int fd, uint32_t events,
                      FfEvCallback cb, void *ctx);
int  ffnet_evloop_mod(FfEvLoop *loop, int fd, uint32_t events);
int  ffnet_evloop_del(FfEvLoop *loop, int fd);

/* Block until ffnet_evloop_stop() is called from within a callback,
 * or until the loop has zero registered fds. Returns FFE_OK or negative. */
int  ffnet_evloop_run(FfEvLoop *loop);
void ffnet_evloop_stop(FfEvLoop *loop);
```

Internal storage: sparse array indexed by fd, holding `{cb, ctx,
event_mask}`. Grows on register; never shrinks (file descriptors recycle).

Stop semantics: `ffnet_evloop_stop` sets an internal flag; the loop
returns at the start of the next iteration. Safe to call from within a
callback or from a signal handler (writes to a self-pipe — see below).

Signal handling: a self-pipe (`pipe()`) is registered with the loop. The
SIGINT/SIGTERM handler writes a byte; the loop's callback for the
read end calls `ffnet_evloop_stop`. This is the standard
self-pipe trick.

### Non-blocking helper + SO_REUSEPORT — `src/libffnet/tcp.c`

Two small additions:

```c
/* Set O_NONBLOCK on fd. Returns FFE_OK or negative. */
int ffnet_set_nonblocking(int fd);

/* Enable SO_REUSEPORT on fd. Call before ffnet_tcp_bind_listen on each
 * worker's listen socket so the kernel can distribute accepts. */
int ffnet_tcp_set_reuseport(int fd);
```

Both are libc-only (`fcntl`, `setsockopt`); no new asm. tcp.asm itself
unchanged.

### High-level server — `src/libffnet/server.c` (new)

```c
/* Run a server: spawn `workers` pthreads, each binds to host:port with
 * SO_REUSEPORT, runs its own event loop, calls proto->open/on_event/close
 * for each client. Blocks until SIGINT/SIGTERM or all workers exit.
 *
 *  workers == 0  is invalid; returns FFE_INVAL.
 *  workers == 1  runs the loop in the calling thread (no pthread spawned).
 *  workers >= 2  spawns pthread per worker; calling thread joins them. */
int ffnet_server_run(const Protocol *proto, const char *host,
                     uint16_t port, int workers);
```

Each worker thread:

1. `ffnet_tcp_create()`, `ffnet_tcp_set_reuseport(fd)`, `ffnet_set_nonblocking(fd)`, `ffnet_tcp_bind_listen(fd, host, port, 128)`.
2. `loop = ffnet_evloop_new()`, register listen_fd with FF_EV_READ → accept callback.
3. Register the worker's self-pipe for SIGINT delivery.
4. `ffnet_evloop_run(loop)`.
5. On exit: drain (best-effort), `ffnet_evloop_free`, close listen fd.

Accept callback:
- Loop `ffnet_tcp_accept(listen_fd)` until FFE_AGAIN (LT epoll → handle the burst).
- For each new client: `ffnet_set_nonblocking(client_fd)`, `proto->open(client_fd, &ctx)`.
- Register client_fd with FF_EV_READ + per-conn callback that invokes proto->on_event and updates the event mask from its return value.

Signal handling: main thread installs `SIGINT`/`SIGTERM` handler that
writes a byte to **all workers' self-pipes**. Workers each see the wake,
call `ffnet_evloop_stop` from their pipe-read callback, exit the loop,
terminate.

### Protocol ABI v3 — `include/ffnet/ffproto.h`

```c
typedef struct Protocol {
    const char *name;

    /* Allocate per-connection state. fd is already non-blocking.
     * Returns FFE_OK and writes ctx into *ctx_out, or negative on failure
     * (framework will close fd and not invoke on_event/close). */
    int (*open)(int fd, void **ctx_out);

    /* Called when one or more requested events fire on fd.
     * `events` is the bitmask of FF_EV_* that fired.
     * Return value:
     *   > 0   new event mask the protocol wants for the next wakeup
     *         (FF_EV_READ | FF_EV_WRITE).
     *   = 0   close cleanly (framework calls close() then closes fd).
     *   < 0   error; framework logs ffutil_strerror_v(rc), then closes. */
    int (*on_event)(int fd, void *ctx, uint32_t events);

    /* Free per-connection state. Framework closes fd after returning. */
    int (*close)(int fd, void *ctx);
} Protocol;
```

`ffproto_find` / `ffproto_register` and `extern const Protocol
ffproto_websocket` are unchanged.

The v2 functions (`server_handshake`, `read_frame`, `write_frame`) are
deleted from both the struct and the WS module. The CLI no longer drives
the per-message loop — it's inside the protocol module's `on_event`.

### WebSocket module rewrite — `src/libffproto/ws/ws_module.c`

`WsConn` becomes the full per-connection state machine:

```c
typedef enum WsState {
    WS_STATE_HANDSHAKE,   /* reading HTTP request, sending 101 response */
    WS_STATE_OPEN,        /* normal frame I/O */
    WS_STATE_CLOSING,     /* sent Close, draining wr_buf then close */
} WsState;

typedef struct WsConn {
    WsState   state;
    FrameBuf  rd_buf;     /* inbound bytes accumulated, not yet parsed   */
    FrameBuf  wr_buf;     /* outbound bytes queued, not yet written       */
    /* Existing fields, preserved: */
    uint8_t   fragment_opcode;
    uint32_t  utf8_state;
    uint8_t   last_opcode;
    /* Handshake-only: bytes consumed so far (for parsing offset). */
    size_t    handshake_parsed;
} WsConn;
```

`on_event` flow:

1. If `events & FF_EV_READ`: read into rd_buf until EAGAIN, EOF, or buffer
   cap reached. EOF → return 0 (clean close, no Close frame because peer is
   already gone).
2. Drive state machine on rd_buf:
   - `WS_STATE_HANDSHAKE`: scan for `\r\n\r\n`. If found, run `find_key` +
     `accept_key`, prepend the 101 response into wr_buf, transition to
     OPEN. If 4 KB exceeded without finding it → protocol error.
   - `WS_STATE_OPEN`: try to parse complete frames from rd_buf. For each
     complete frame, run the existing fragmentation + UTF-8 logic.
     Completed data messages get echoed (queued to wr_buf with the
     correct opcode). Close frames trigger `WS_STATE_CLOSING` (queue a
     reciprocal Close to wr_buf if not yet sent).
   - `WS_STATE_CLOSING`: only drain wr_buf; no more reads.
3. If `events & FF_EV_WRITE` (or step 2 queued bytes): write from wr_buf
   until EAGAIN or buffer empty.
4. Determine next event mask:
   - FF_EV_READ if state != CLOSING and rd_buf < cap.
   - FF_EV_WRITE if wr_buf has pending bytes.
   - 0 (close) if state == CLOSING and wr_buf is empty.

The existing helpers (`read_one_frame`, `validate_text_chunk`,
`ws_close_with`) are refactored to operate on rd_buf and wr_buf instead of
on fd directly. The hot-path asm (`_ff_asm_ws_unmask`,
`_ff_asm_ws_find_key`, `_ff_asm_ws_accept_key`,
`_ff_asm_ws_send_response`) is unchanged — only the C glue changes.

`ws_handshake.asm::_ff_asm_ws_send_response` currently calls `sys_write`
itself. We need a buffer-only variant or stop using the asm version for
the response (the response is built in C and queued to wr_buf). Cleanest:
add a new internal function `ws_build_response(accept_key, accept_len,
out_buf)` that builds the response bytes in a caller-provided buffer
without writing. Keep the asm version available for callers that want
"build + write in one syscall" (currently nobody — slated to be deleted
when nothing references it). For now, the C side builds the response
inline; the asm `_ff_asm_ws_send_response` becomes dead code that we
**delete** at the end of this slice to keep ws_handshake.asm lean.

Adds `--workers N` (default 1). The "listening on ..." stdout line moves

### CLI — `cli/cmd_tcp_echo.c` (new)

Raw TCP echo, no protocol module:

```c
/* TcpEchoConn is its own tiny "protocol" implemented inline in this file.
 * Uses ffnet_server_run directly with a one-off Protocol struct. */

static int tcp_echo_open(int fd, void **ctx_out) {
    *ctx_out = NULL;
    return FFE_OK;
}

static int tcp_echo_on_event(int fd, void *ctx, uint32_t events) {
    (void)ctx;
    uint8_t buf[4096];
    if (events & FF_EV_READ) {
        ssize_t n = read(fd, buf, sizeof buf);
        if (n == 0) return 0;
        if (n  < 0) {
            if (errno == EAGAIN || errno == EWOULDBLOCK) return FF_EV_READ;
            return ffutil_map_errno(-errno);
        }
        /* For raw echo we write back inline (best-effort). A real protocol
         * would buffer; this is a demo. */
        ssize_t w = write(fd, buf, n);
        if (w != n) return ffutil_map_errno(-errno);
    }
    return FF_EV_READ;
}

static int tcp_echo_close(int fd, void *ctx) { (void)fd; (void)ctx; return FFE_OK; }

static const Protocol g_tcp_echo = {
    .name = "tcp-echo", .open = tcp_echo_open,
    .on_event = tcp_echo_on_event, .close = tcp_echo_close,
};

int cmd_tcp_echo(int argc, char **argv) {
    /* ...args... */
    return ffnet_server_run(&g_tcp_echo, host, port, workers);
}
```

(The inline write is acceptable for a raw demo. WS module's wr_buf
discipline is what handles real protocols correctly.)

`cli/ffnet.c`'s g_cmds[] gets a second entry.

## Verification

End-to-end check on shaiman:

```sh
make clean && make           # builds clean with -lpthread, no warnings
make test                    # all unit tests including new test_evloop
make itest                   # extended: single + parallel WS client variants
make autobahn                # ≥ 96.3% strict pass, zero FAILED

python3 tests/test_tcp_echo.py 127.0.0.1 9100   # 8 parallel clients pass
```

The Autobahn re-run is the most important checkpoint: confirms the
state-machine ws_module is RFC-equivalent to the blocking one.

## Risks and open questions

1. **Asm + pthread interaction.** Our asm routines use callee-saved
   registers correctly per SysV AMD64. pthread doesn't impose additional
   requirements beyond ABI. Verified by review of sha1.asm, base64.asm,
   tcp.asm — no thread-local-storage usage, no global asm state. Safe.

2. **`ffutil_strerror_v` thread-safety.** Returns a pointer to a static
   buffer (slice 1.5 note flagged this). With N workers each potentially
   logging concurrently, the buffer races. Fix: make the static buffer
   `__thread` (TLS) in slice 1.7. Compiler support is universal on
   Linux/x86_64.

3. **`ffproto_register` thread-safety.** Currently mutex-free. Workers
   only **find** protocols (read-only on the static table); registration
   is single-threaded at startup. Document this constraint in the
   `ffproto_register` comment; defer locking to a slice that actually
   needs runtime protocol registration.

4. **Write buffer unbounded growth.** wr_buf could grow if peer never
   reads. Slice 1.7 adds no cap; document as accepted risk. Slice 1.8
   should add `WS_MAX_WRITE_BUF` with backpressure (Close 1009).

5. **Sparse fd array max size.** Theoretical fd cap is `RLIMIT_NOFILE`
   (default 1024 on Ubuntu, raisable). Slice 1.7 allocates the array up
   to the highest fd seen — fine for hundreds of clients per worker.
   Documented; no hard cap enforcement.

6. **Linux-only.** epoll is Linux-specific. The eventloop.c file will
   eventually have kqueue/IOCP siblings (a slice 4+ multi-OS effort);
   the public `FfEvLoop` API is intentionally opaque so consumers won't
   have to change.

7. **Autobahn run mode.** The current `tests/autobahn/run.sh` starts
   `ffnet ws-echo --listen 0.0.0.0:9001`. After this slice, that's still
   the same invocation (--workers defaults to 1). The post-1.7 run
   becomes a sanity check that the state-machine rewrite matches the
   blocking version's compliance.

## Out of scope (deferred)

- Edge-triggered epoll (`EPOLLET`) — slice 1.8 perf.
- Backpressure / max-write-buf — slice 1.8 (mentioned in risk 4).
- Timer wheels / per-connection idle timeouts — slice 2 (HTTP keep-alive
  needs them).
- TLS — slice 3.
- Multi-OS (kqueue, IOCP) — slice 4+.
